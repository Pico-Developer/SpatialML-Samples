# YOLO Object Detection

This sample builds an application for PICO using the SpatialML
APIs. The application demonstrates real-time object detection
using the [YOLOX-M LiteRT model](https://huggingface.co/litert-community/yolox-m-litert)
in TFLite format on the Qualcomm NPU.

![Demo of YOLO making detections on objects on the desk](../../../docs/Demo-YOLO.gif)

### Code Walk-through

The implementation follows a dependency-chained pipeline architecture:

1. **VST Image Pipeline**
   - Reads the stereo camera feed as uint8 BGR
   - Converts the left camera image to the model's float32 0-255 input
   - Manages camera timestamps and matrices

2. **Model Inference Pipeline**
   - Runs YOLOX-M on the Qualcomm NPU

3. **Post-processing and NMS Pipelines**
   - Uses a compiled LiteRT postprocessor for class selection, YOLOX decoding, and top-128 selection
   - Runs CPU NMS only on the 128 strongest candidates instead of all 8,400 anchors
   - Uses class-aware NMS, allowing persistent detections of different classes
     at the same image location to survive independently
   - Outputs up to ten bounding boxes, class IDs, and confidence scores

4. **2D to 3D Mapping Pipeline**
   - Maps 2D detection results to 3D space
   - Calls `uv2Cam` for the center of each selected detection
   - Generates 3D coordinates for detected objects

5. **Label and Rendering Pipelines**
   - Visualizes detection results in the XR environment
   - Uses one glTF model containing ten frame nodes, ten independently movable
     label nodes, and ten label textures, avoiding one Vulkan model allocation
     per detection
   - Converts each decoded pixel width and height into world dimensions using
     the captured camera focal lengths and reconstructed render depth; the box
     therefore preserves the detector's angular extent instead of using a fixed
     pixel-to-world divisor
   - Sizes each horizontal label from its detected box width, clamped to 80-112
     source-camera pixels; the label keeps a 4:1 aspect ratio for readability
   - Assigns each detection slot a distinct high-contrast color shared by its
     frame and label text
   - Formats each label as `class confidence%` (for example, `chair 92%`) in a
     single texture draw so the score appears beside the class name
   - Attaches labels to the left or right top corner of each box. In descending
     confidence order, a label whose preferred top rectangle intersects an
     earlier visible label is moved to the matching bottom corner of its box,
     preserving both labels while matching colors retain box association
   - Refreshes the relatively expensive class-label textures at a lower cadence
   - Updates bounding-box poses independently at the detection cadence
   - Handles scale and positioning of visual elements

### Key Components

The `YoloDetector` class in `programmatic/cpp/yolo_object_detection.h` manages:

- **Framework Setup**: Initializes SpatialML runtime and pipeline components
- **Pipeline Management**: Creates and dependency-chains the camera, NPU inference, post-processing, NMS, mapping, label, and rendering stages
- **Data Flow**: Uses GlobalTensors for inter-pipeline communication
- **Resource Management**: Handles GLTF assets and tensor memory
- **Scheduling**: Targets a stable 100 ms cadence for ten positioned detections while allowing rendering to overlap the next detection

### Configuration

- Base model: `yolox_m.tflite`
- Runtime model: `assets/yolo_det_programmatic/yolox_m.tflite`
- Postprocessor: `assets/yolo_det_programmatic/yolox_postprocess.tflite` (generated by `tools/generate_yolox_postprocess.py`)
- Input: 640 x 640 BGR float32 in the 0-255 range
- Output: 8400 x 85 raw YOLOX heads, reduced to 128 pre-NMS candidates by the postprocessor
- Model target: LiteRT NPU
- Detection cadence: 100 ms (10 FPS target for ten UV2Cam points and labels)
- Maximum visible detections: ten
- Visible detection confidence threshold: 0.50
- Temporal confirmation toggle: `kRequireConfirmedDetections` (enabled)
- Confirmation requirement: three consecutive same-class detections matched at IoU > 0.40
- GLTF asset path: `frame2_multi_10.gltf`
- Multi-detection asset generator: `tools/generate_multi_detection_gltf.py`
- Label texture template: 512 x 128, generated by `tools/resize_gltf_texture.py`
- Supports both left and right camera inputs for stereo processing

On `PB311XHGKC150061G`, OpenMR operator tracing measured approximately 11 ms
for NPU inference, 1.9 ms for compiled CPU post-processing, and 0.4 ms for CPU
NMS. The camera's uint8-to-float32 conversion remains the largest host-side
stage at approximately 27 ms; `uv2Cam` cost scales with the selected detection
count.

Do not replace this model with a UINT8-input wrapper on the tested Qualcomm
dispatch runtime. Although such a wrapper is numerically equivalent on the host,
on-device testing produced zero detection confidences.

### Technical Details

The implementation uses SpatialML's pipeline architecture for efficient:
- Tensor operations
- Multi-threaded execution
- Hardware-accelerated processing
- XR session management
- Real-time visualization

Stages are linked with pipeline run handles so each inference uses the matching
camera frame. Labels render on each of the first three submissions so a
three-frame-confirmed detection receives its text before the box and label
become visible. Label rendering then switches to every 15 submissions because
recreating a text texture costs substantially more than updating a box pose.

### Build and run

```sh
./gradlew :samples:yolo_det:installDebug
```

Launch **YOLO Object Detection**, grant camera permission, and look toward recognizable objects. The app renders up to ten non-max-suppressed detections with class labels. Successful runtime logs contain repeated `OpenMR: executePipeline ... err: 0` entries.
